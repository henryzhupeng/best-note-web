# 优记 BestNote · Web v7.31

这是一个可直接在浏览器打开的高保真交互网页版，覆盖产品需求文档中的 MVP 核心路径：

- 批量上传最多 20 张图片，自动推荐学习、工作、兴趣、会议、健身、阅读、项目、旅行、食谱或投资模板
- 独立 OCR 与批量图片 AI 整理都使用真实 OCR
- 批量图片会按识别正文生成相关标题、标签、段落、列表和表格
- 模板不再返回固定占位内容，所有结构都由本次识别正文生成
- 独立图片转文字入口：真实 OCR、语言选择、逐图进度、置信度、编辑、复制与保存
- OCR 后处理：清理标点、异常空格和错误断行
- 删除状态栏、页码、平台按钮、水印、URL 和重复行等截图噪声
- 自动识别标题、键值对、列表、正文段落和表格，并生成对应的便签式结构
- 使用连续线条检测区分表格边框和文字行，避免文字行被误判为表格行
- 只保留位于表格区域内的行列线，过滤标题装饰线和正文边缘
- 表格会检测网格线、移除线条干扰，并逐个单元格进行 OCR
- 保留原图检测到的行列数和空白单元格，避免空单元格导致列错位
- 低置信度单元格会使用对比增强版本进行第二轮识别
- 自动识别失败时，可在便签预览中点击“识别为表格”强制按行列整理
- 识别后的表格保留表头和多列数据，在预览及保存后的笔记中渲染为表格样式
- 对规则表格效果最佳；复杂合并单元格、手写表格或低清截图仍建议人工核对
- 结果预览和笔记详情参考 Apple Notes 的白底、简洁字体和段落层级
- 过滤图形、图标、线条、符号碎片和低置信度文字，避免误识别为正文
- 根据全文领域强度和正文重点生成标题，少量无关词不会改变主标题
- 提供 3 个主题相关候选标题，支持修改、切换和重新生成
- 内置“使用示例图片”，可一键验证 OCR 是否正常工作
- 上传新截图时会自动替换上一批 OCR 图片，避免新旧截图混合识别
- 支持清空全部图片，识别处理中会锁定文件操作
- 每条笔记卡片提供置顶、合并和删除快捷操作，可切换“置顶 / 含表格”筛选
- 笔记列表支持文件夹筛选、多选合并，以及合并后自动将原笔记移入回收站
- 合并后的内容按原笔记标题分节，保留表格、列表和标签
- 笔记详情支持直接编辑表格，并可增加行、删除行、增加列、删除列
- 右上角回收站入口、删除数量角标、恢复、永久删除和一键清空
- 笔记列表、文件夹筛选、全文搜索、本地备份导入与导出
- 导出 Markdown、JSON、Excel 兼容表格（`.xls`）和纯文本
- 浏览器 IndexedDB 主存储 + localStorage 兜底，可安装为 PWA（手机主屏 / 桌面应用）
- 自动保存版本历史，可恢复误删、误改和错误的表格调整
- 表格支持合并单元格、取消合并和撤销/重做
- 支持手机拍照、相册和剪贴板截图快捷导入
- 内置 8 条真实示例笔记和可视化自检页

## 当前限制

这是用于产品验证和交互演示的前端原型：

- 独立 OCR 默认使用浏览器端 PaddleOCR-WASM，可读取图片真实文字
- 首次 OCR 需要联网下载 PaddleOCR-WASM 和中文模型，后续会由浏览器缓存
- 标题生成使用本地领域评分规则，不调用外部大模型
- 图形过滤基于 OCR 置信度、文字占比和区域类型，极复杂图片仍建议人工核对
- 批量图片整理使用本地规则完成语义分块；接入大模型后可以进一步提升摘要和合并质量
- 图片仅在当前浏览器会话中预览，刷新页面后需要重新选择
- 笔记保存在当前浏览器的 IndexedDB，不会跨设备同步；可用 JSON 备份迁移
- `.xls` 导出为 Excel 可直接打开的 HTML 表格，不是原生 XLSX

## OCR 架构（v7.23）

优记的图片识别完全在浏览器本地完成，不经过任何服务器：

- 默认引擎：PaddleOCR-WASM（`@paddlejs-models/ocr`），通过 jsDelivr 按需加载，首次使用下载中文模型并在浏览器缓存
- 图片仅在用户浏览器内处理，不上传、不落盘到服务器
- 识别失败、手写或模糊图片时，使用工具栏「AI 增强识别」下拉，跳转豆包 / Kimi / DeepSeek，用用户自己的账号额度手动识别后粘贴回来
- 全程无后端、无 Token、无 iframe、不调用任何大模型 API

关键入口：

- `runOcrRecognition()`：独立 OCR 页面
- `runAiOrganize()` / `runPaddleJsAiOrganize()`：批量图片整理
- `aiEnhanceDropdown()` / `copyAiOcrPrompt()`：AI 增强下拉与 prompt 复制
- `AI_OCR_PROVIDERS`：第三方 AI 列表，新增服务只需改这一处 JSON

未来如需接入付费高精度 API 自动回填，可在 `runPaddleJsOcrRecognition()` 失败分支新增引擎，与当前免费方案共存，不影响现有路径。

## PaddleOCR-WASM 与 AI 增强兜底

- 本机已安装 `paddleocr-text-recognition` 与 `paddleocr-doc-parsing` 两个 Skill，可用于离线批量校验识别效果。
- 网页默认使用 PaddleOCR-WASM 在浏览器本地识别，不上传图片、不调用云端 OCR API。
- 识别效果较差、手写或模糊的图片，点击工具栏「AI 增强识别」，选择豆包 / Kimi / DeepSeek，新标签页打开对应服务并自动复制 prompt，识别结果手动粘贴回编辑器。
- 模型加载失败时页面提示「模型加载失败，可使用 AI 增强识别兜底」，任何场景都不会清空编辑器已有内容。

> 当前版本不依赖任何 PaddleOCR 云端凭证或后端 API。`server.rb` 是历史本地预览脚本，静态部署不需要它。

## v7.30 重点更新

## v7.29 重点更新

- **修掉识别结果「上下不统一」**：预览里同一段文字一会儿是小标题、一会儿是正文
  - 原因：标题判定里有一条「上一行是空行」的规则，但 `normalizeOcrText` 早就把空行删了，
    这条规则实际上永远不生效，只剩「第一行算标题」在起作用 —— 于是同一行在不同位置表现不一致
  - 现在改成只依据内容 + 相邻行判断：固定小标题词表 / 以冒号结尾 / 短行且下一行明显更长 / 文档第一行
- **重复段落自动去重**：截图上下重复、拼接重叠导致同一段话出现两次时，只保留第一次（≥8 字才去重，短句和表格不受影响）
- **便签正文统一纵向节奏**：`.detail-content` 的 h3 / p / ul 用同一套间距（块间 10px、标题上方 22px），
  不再出现有的地方挤、有的地方空
## v7.28 重点更新

## v7.27 重点更新

- **找回 Tesseract.js 作为本地备用引擎**（v7.23 之前用的就是它，一直能在国内网络下正常工作）
  - 为什么它能用：`tesseract.js` 的 **worker 脚本、wasm core、中文语言包默认全部来自 `cdn.jsdelivr.net`**，
    而这个域名在你的网络里是通的（PaddleOCR-WASM 挂在 `bcebos.com` 上，所以一直连不上）
  - 语言：`chi_sim+eng`，OEM=LSTM，模型下载一次后由浏览器缓存
- 本地引擎重新变回两个，可手动切换，也会在失败时自动互备（只切一轮，不会来回循环）：
  | 引擎 | 模型来源 | 特点 |
  |---|---|---|
  | PP-OCRv4 (ONNX)（默认） | hf-mirror.com | 更准，首次约 15MB |
  | Tesseract | cdn.jsdelivr.net | 兼容性最好，国内基本都能下 |
- OCR 页恢复「本地引擎」下拉；任一引擎失败时自动换另一个重试，两个都失败才提示改用「AI 增强识别」

BestNote 不和苹果备忘录比 OCR 精度。苹果便签擅长图片文字原样提取，BestNote 专注把任意来源的文字加工成课堂笔记、错题、参数表、阅读摘要或会议行动项。图片 OCR 保留为基础输入入口，不再作为核心卖点。

## 手机打开方式

当前只用一个静态服务器即可，同一 Wi-Fi 下手机可以访问：

1. 在 Mac 项目目录启动静态服务：`ruby -run -e httpd . -p 4175 -b 0.0.0.0`
2. 查看 Mac 局域网 IP：系统设置 → 网络 → Wi-Fi → 详细信息
3. 手机浏览器打开：`http://Mac的局域网IP:4175`
4. 点击页面中的“安装到手机 / 桌面”，或使用浏览器“添加到主屏幕”
5. 安装后可以从微信、相册等应用通过系统分享菜单发送截图到“优记”

> 如果 PWA 安装入口没有出现，通常是浏览器要求 HTTPS 或 `localhost`。iPhone 可用 Safari 的“添加到主屏幕”；Android Chrome 可用菜单中的“安装应用”。

## 文件夹怎么用

1. 打开左侧“全部笔记”。
2. 点击右上角“＋ 新建文件夹”。
3. 输入名称，例如“客户会议”“健身计划”或“旅行资料”。
4. 打开优记，在标签右侧的“文件夹”下拉框中选择目标文件夹，再点击“保存修改”。
5. OCR 和批量 AI 保存前可以点文件夹旁的“新建”，直接创建并选中，不会丢失当前草稿。

自定义文件夹会写入 IndexedDB，并包含在 JSON 备份中。

## 本地识别引擎（两个都在浏览器本地跑）

优记内置两个本地 OCR 引擎，在 OCR 页的「本地引擎」下拉里切换，选择会记住：

| 引擎 | 特点 | 适用 |
|---|---|---|
| **PaddleOCR-WASM**（默认） | 走 Paddle.js，模型小、加载快 | 清晰截图、常规印刷体 |
| **PP-OCRv4 (ONNX)** | 走 onnxruntime-web + PP-OCRv4 det/rec 模型，识别率更高 | 小字号、表格、稍糊的截图 |

- 两者都**完全在浏览器本地运行**：模型从 CDN 下载一次后由浏览器缓存，图片不上传、无 Token、无 API
- ONNX 引擎首次使用约需下载 15MB 模型，之后离线可用
- 模型来源写死在 `ocr-onnx-engine.js` 顶部的 `DEFAULTS`，含多个 CDN 回退（HuggingFace / hf-mirror / jsDelivr）
- 如果加载失败，页面会提示，可退回 PaddleOCR-WASM 或使用 AI 增强识别

## OCR A/B 对比（诊断页）

打开 `ocr-ab-test.html`（或从 OCR 页点击「A/B 对比」）：

- **A 列**：用 PaddleOCR-WASM 直接识别原图
- **B 列**：先做图像增强（灰度 + 对比度拉伸 + 2× 放大，或 Otsu 二值化）再识别
- 两列并排显示文字、行数、字符数、质量分、耗时，并给出逐行差异与一致率
- 可以判断「是图像质量拖累了识别」还是「模型本身不认」

如果想接入第二个真正的引擎（例如 ONNX Runtime Web + PP-OCRv4/v5），只需在页面加载后注册：

```js
window.BestNoteAltOcr = {
  // 返回纯文本即可
  recognize: async ({ url, mode }) => {
    return await myEngine.recognize(url);
  }
};
```

注册后 B 列会自动改用外部引擎，A 列仍是 PaddleOCR-WASM，两边互不影响。该页全程本地运行，不上传图片、不调用任何 API。
